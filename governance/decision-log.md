### 2026-09-13 — EMA crossover strategy spec approved; one year of 1h data cannot prove an edge
- **Decision:** CEO approval of the EMA crossover rules and dashboard spec, completing the gate the founder set (analyst → CFO → CEO, no founder signature). Approved: `specs/2026-09-13-ema-crossover-btc-1h-rules-and-dashboard-v1.md`, `specs/2026-09-13-bar-data-backtest-annex-v1.md`, the two-tier grid, the paired block bootstrap, and gate 2 narrowed to a single pre-declared out-of-sample candidate.
- **What was approved is a specification and a protocol.** No BTC data exists in this firm, no backtest has been run, and no result about real BTC is implied.
- **The finding that reframes the initiative:** the CFO calculates the standard error of an annualized Sharpe on ~2,090 tradeable holdout bars at **~2.05** (Lo-2002 closed form, iid, labelled an approximation and a floor). A measured Sharpe of 1.5 therefore spans roughly **[-2.5, +5.5]**. One year of 1h data on one instrument cannot produce a statistically significant edge claim. It can produce a pipeline, a protocol, a dashboard, and a defensible "no edge found". Surfaced to the founder immediately rather than at stage 11, per firm rule 6.
- **Two reviewer calls worth recording:** the CFO rejected the analyst's recommendation to fill stops at the bar extreme, because it is uniformly punitive on stop-bearing variants only and therefore biases the grid away from them — a cost model that changes which strategy wins is worse than one slightly optimistic. And they banned emitting v1's five-component cost attribution in bar mode, where three of five inputs would be invented, in favour of a bar-specific three-component identity with nulls carrying reason codes rather than zeros.
- **Alternatives considered:** sending the pre-registration back rather than amending it (rejected — the CFO owns the amendments as reviewer and the artifact was sound); authorizing the matched-multiplicity null over the full 14,256-configuration grid (rejected by the CFO at >1.4e7 backtests, correctly); raising the paper policy's gate-2 Sharpe bar in response to the analyst's 23% noise finding (rejected — that figure is in-sample best-of-grid while gate 2 is a single OOS candidate, so the fix was to narrow applicability, not raise the bar).
- **Approved by:** analyst → CFO (with changes) → CEO. Founder approval not required at this gate by the founder's own instruction; founder final review still applies to the finished system at stage 11.
- **What would reverse this:** a longer or higher-frequency dataset, or more instruments, which is the only thing that would make a significant edge claim possible on this strategy family.

### 2026-09-13 — Data transport exists via GitHub; the source does not yet
- **Measured, in response to the founder's suggestion to use Yahoo Finance, TradingView or a connector:** Yahoo (`query1`/`query2.finance.yahoo.com`), Binance (`api.binance.com`, `data.binance.vision`) and `cryptodatadownload.com` all return `000` — unreachable. The **Alpha Vantage MCP connector is live** (`PING` → `pong`) but `CRYPTO_INTRADAY` is a **premium endpoint** on this key, so 1h crypto bars are not available through it. **GitHub is fully reachable**: `raw.githubusercontent.com` returns 200 for an arbitrary public repo's file, `api.github.com/rate_limit` 200, and `git clone` of an arbitrary third-party public repo succeeds. `pypi.org` is reachable, so `yfinance` installs — but its data host is blocked, so installing it achieves nothing.
- **Conclusion:** the founder's storage suggestion works and doubles as a transport. What is missing is a **source**. GitHub's search API is blocked for this session ("sessions are bound to their configured repositories"), so a dataset cannot be discovered from here — only fetched once its exact path is known.

- **Caveat recorded now, before anyone builds on it:** a third-party GitHub CSV is **not venue data**. Provenance, exchange timestamps, gap handling, revisions and licence are all unverified, and the CLO is on hold. Usable for a first EMA crossover backtest only if labelled unvalidated third-party data, never as a venue-sourced result. The CFO has separately found that capacity is not estimable from bar data at all, which stands as a block on any later live promotion regardless of source.
- **Approved by:** CEO, pending the founder's choice
- **What would reverse this:** option (2), which would make options (1) and (3) unnecessary.

### 2026-09-13 — Venue egress is blocked in this environment; split the data work
- **Finding, verified twice:** every venue API and documentation host is unreachable from this environment. The backend developer measured it, the CTO escalated it, and the CEO confirmed it independently: `docs.cdp.coinbase.com`, `api.exchange.coinbase.com` and `www.topstep.com` all return `000` (no connection), while `pypi.org/simple/` — which the agent proxy's `noProxy` list permits — returns `200`. The proxy reports `enabled: true`, `selective: false`. Package registries are reachable; venues are not.
- **Consequence:** two things the firm's own rules require cannot be done here. The mandate says no venue specific may be stated from memory and must be read from current documentation and cited — unexecutable. And no market data can be fetched, so no snapshot, so no backtest on real data. `specs/2026-09-13-cost-and-fill-model-v1.md` §16.1 already records that no venue document of any kind has been retrieved by this firm.
- **Decision:** adopt the CTO's split rather than stopping. Gap 3 becomes a **store and reader, buildable now against synthetic fixtures**, and a **fetcher, blocked**. The engine, risk gate, determinism harness, accounting invariants and the whole QA assertion catalogue need no venue access and can proceed. Nothing that depends on a real venue value is built until the value exists.
- **Escalated to the founder, three options:** (1) widen the environment's network policy to allow the four venues' documentation and API hosts — the clean fix, and the only one that makes the mandate's citation rule executable; (2) the founder supplies a data snapshot and the venue rulebooks out of band; (3) proceed on synthetic data only and accept that no result means anything about a real market until (1) or (2) happens.
- **Approved by:** CEO, pending the founder's choice among the three
- **Record:** `workspaces/engineering/work/2026-09-13-cto-review-round.md`
- **What would reverse this:** option (1) or (2), at which point the fetcher unblocks and the citation rule becomes enforceable again.

### 2026-09-13 — Adopt the founder's mandate and fix the venue universe at four
- **Decision:** Publish the firm's goal — *build profitable strategies that can be built, automated and executed with minimum human efforts* — as `specs/2026-09-13-firm-mandate-v1.md`, and fix the available markets at **Topstep, Webull, Coinbase and Polymarket**. Wired into `CLAUDE.md` so every session carries it, and into all nine agent definitions with the implications specific to each role. Seven decision heuristics make it a tiebreaker rather than a slogan, the sharpest being: automatable beats profitable-on-paper, and a venue without programmatic access is not a venue for this firm.
- **Rationale:** A goal that lives only in conversation cannot be applied by an agent that was not in that conversation. Putting it in the charter and each definition means it is loaded before any work starts; putting it in `specs/` with a version gives proposals something citable. - **Two things deliberately pinned down:** (1) **Minimum human effort never means fewer approvals** — automation covers the work (ingest, backtests, deployment, recovery, reconciliation, monitoring, and execution within already-approved limits), while the founder's gates stay human; a design that moves an approval into code is a charter violation, not an efficiency. (2) **No venue specifics from memory** — no rule, fee, API capability, rate limit, licence term or legal status for any of the four may be stated from recall; each has a named verification owner, and Topstep's rulebook is an externally imposed risk limit that binds before our own policy.
- **Alternatives considered:** Stating the goal only in `CLAUDE.md` (rejected — nothing for a proposal to cite, and no per-role implications); leaving the venue list open (rejected — unbounded research is the overfitting machine the CFO warned about); naming a single venue now (rejected — that is the founder's call, though Coinbase is recommended first, Topstep second).
- **Approved by:** Founder (set the goal and the market list) → CEO
- **Record:** `specs/2026-09-13-firm-mandate-v1.md`

### 2026-09-12 — Bound each agent to a workspace, and make the hierarchy the only channel
- **Decision:** Give every agent a bounded workspace and allow direct messaging only between roles that share one. Five rooms: `exec` (CEO, CFO, CTO, CLO), `finance` (CFO, analyst, trader), `engineering` (CTO, backend, frontend, QA), `legal` (CLO), `founder` (CEO). The CFO, CTO and CLO are the only bridges out of their team rooms; the CEO is the only bridge to the founder. Cross-team artifacts are published to `specs/`. Membership and write access live in `workspaces/registry.json`; `scripts/msg.py` refuses a route that does not exist and `scripts/check_boundaries.py` audits what was written.
- **Rationale:** Separation of duties only holds if it is structural. With the walls in place there is no channel by which anyone but the CFO could instruct the trader, no way for the analyst to task a developer directly, and no way for a team's unreviewed work to reach the founder — an executive has to carry it, and carrying it means owning it. It also keeps each agent's attention on its own room rather than the firm's whole traffic.
- **Alternatives considered:** One shared workspace for all nine (rejected — no structural separation, and the trader becomes reachable by anyone); per-agent private directories with no shared rooms (rejected — the CFO needs to work *with* the analyst and trader, not just receive files); relying on agent instructions alone (rejected as insufficient on its own — hence the refusing helper and the audit script, since Claude Code cannot enforce per-agent filesystem scopes).
- **Approved by:** Founder (directed this structure)
- **Record:** —
- **What would reverse this:** The ten-hop cross-team path proving too slow in practice, in which case the fix is a documented direct channel for a specific pair (e.g. analyst ↔ backend for spec clarifications) rather than removing the walls.

### 2026-09-12 — Establish the agent org structure for Bitbull Capital
- **Decision:** Stand up the firm as a nine-agent team — CEO, CFO (with market analyst and trader), CTO (with backend, frontend and QA), CLO — with the founder as final approver on every gate.
- **Rationale:** Startup phase needs a small team with clear ownership and hard gates in front of real money. The chain of command keeps research, approval, and execution separated so no single agent can take the firm from an idea to a live order.
- **Alternatives considered:** A flat set of agents with no reporting lines (rejected — no review step before capital is committed); C-suite only, no sub-teams (rejected — the founder asked for the analyst/trader and developer teams, and the separation of research from execution is the control that matters most).
- **Approved by:** Founder (directed this structure)
- **Record:** —
- **What would reverse this:** The structure proving too heavy for the firm's size, or a change in how the founder wants to interact with the team.
